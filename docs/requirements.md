# ПР1 — Техническое задание
**Тема:** Разработка веб-приложения для конфигурирования компьютерных комплектующих.

## Предметная область
Покупатель компьютера должен подобрать совместимые детали и оценить стоимость будущей сборки. При ручном подборе легко ошибиться с сокетом процессора, типом памяти, мощностью блока питания и размерами видеокарты. Веб-приложение предоставляет каталог комплектующих с характеристиками. Посетитель может искать и фильтровать товары. Зарегистрированный пользователь собирает ПК, сохраняет варианты и возвращается к ним позже. Сервер проверяет ограничения совместимости перед сохранением. Администратор обновляет каталог и справочники. Система не выполняет реальные платежи и не резервирует складские остатки: поле stock служит проверке доступности.

## Роли
**Гость:** каталог, поиск, карточки, регистрация и вход. **Пользователь:** возможности гостя, создание, просмотр, изменение и удаление только собственных сборок. **Администратор:** управление категориями, комплектующими и правилами, статистика; не получает доступ к чужим сборкам через пользовательский API.

## Функциональные требования
1. Система должна позволять регистрироваться с уникальным email и паролем длиной не менее 8 символов.
2. Система должна позволять входить по email и паролю и получать токен.
3. Система должна позволять завершать сеанс с отзывом текущего токена.
4. Система должна позволять просматривать каталог и отдельные карточки деталей.
5. Система должна позволять искать детали по части названия.
6. Система должна позволять фильтровать детали по категории, бренду и цене.
7. Система должна позволять сортировать каталог и переключать страницы.
8. Система должна позволять администратору создавать комплектующие.
9. Система должна позволять администратору изменять и удалять неиспользуемые комплектующие.
10. Система должна позволять администратору управлять категориями.
11. Система должна позволять авторизованному пользователю создавать собственную сборку.
12. Система должна позволять редактировать и удалять собственные сборки.
13. Система должна позволять проверять сокет CPU и материнской платы.
14. Система должна позволять проверять тип RAM и материнской платы.
15. Система должна позволять проверять запас мощности БП не менее 20%.
16. Система должна позволять проверять длину GPU относительно корпуса.
17. Система должна позволять рассчитывать стоимость выбранных компонентов.
18. Система должна позволять администратору получать сводную статистику.

## Нефункциональные требования
НФТ-1: сервер — PHP 8.3+ и Laravel 12, REST API. НФТ-2: обмен JSON с `Accept: application/json`. НФТ-3: хранение — MySQL 8. НФТ-4: Bearer-токены Sanctum, срок жизни 1440 минут. НФТ-5: пароли — только хеш, права проверяются middleware и Policy. НФТ-6: документация маршрутов и примеры в Postman. НФТ-7: CORS ограничен адресом клиента. НФТ-8: ответ списка содержит `data`, `links`, `meta`; серверная пагинация. НФТ-9: ошибки возвращают JSON с `message`, валидация с `errors`. НФТ-10: тесты запускаются командой `php artisan test`.

## Ключевой сценарий
1. Пользователь входит и получает Bearer-токен.
2. Выбирает компоненты и нажимает «Проверить и сохранить».
3. API проверяет токен, Form Request проверяет ID, количество и уникальность позиций.
4. Сервис открывает транзакцию и блокирует выбранные строки компонентов (`lockForUpdate`).
5. Проверяются активность и остаток каждого товара, отсутствие двух компонентов одной категории.
6. Проверяются сокет CPU/платы, тип RAM, запас мощности БП и длина GPU относительно корпуса.
7. При нарушении бизнес-правила сервер возвращает 409 и сообщение, транзакция откатывается.
8. При успехе сохраняются позиции и стоимость, возвращается JSON с кодом 201.
9. При отсутствии токена — 401, чужая сборка — 403, несуществующий ID — 422 или 404, неверные поля — 422.

## Стек
PHP выполняет серверный код; Laravel организует маршруты, валидацию, middleware и обработку ошибок. Eloquent ORM связывает модели с таблицами и упрощает запросы; Composer управляет зависимостями PHP. MySQL хранит каталог и сборки, Sanctum выдаёт и проверяет токены. Laravel выбран из-за готовой инфраструктуры REST API, миграций, политик и тестирования.
